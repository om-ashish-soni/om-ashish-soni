- Read and patch Linux kernel subsystems (sched, mm, net/tcp).
- Fluent C and Rust.
- First upstream Linux patch merged.
- Working eBPF tool shipped.
- A transformer re-implemented from scratch (nanoGPT-level).

## Systems Track — Resources

### Books (Kindle order)
1. **CSAPP** — Bryant & O'Hallaron, *Computer Systems: A Programmer's Perspective* — canonical bridge from code to hardware.
2. **The Rust Programming Language** — Klabnik & Nichols — free online + Kindle.
3. **OSTEP** — Arpaci-Dusseau, *Operating Systems: Three Easy Pieces* — free PDF, sideload to Kindle.
4. **Linux Kernel Development** — Robert Love — readable kernel overview.
5. **The Linux Programming Interface (TLPI)** — Michael Kerrisk — the reference; skim, then deep-dive.
6. **Understanding the Linux Kernel** — Bovet & Cesati — older but dense on mm/sched.
7. **Computer Organization and Design, RISC-V Ed.** — Patterson & Hennessy.

### Courses
- **CMU 15-213** (CSAPP companion) — lectures + labs (bomb lab, malloc lab, shell lab).
- **MIT 6.1810 (ex-6.828)** Operating Systems Engineering — xv6 labs are *the* OS rite of passage. Site: `pdos.csail.mit.edu/6.828/`.
- **UC Berkeley CS162** — alternative OS course with Pintos.

### Papers (read + re-write as notes)
- Ulrich Drepper — *What Every Programmer Should Know About Memory* (2007, still essential).
- Brendan Gregg — *USE Method* and *Flame Graphs* papers.
- Jonathan Corbet's LWN articles on Linux subsystems.

### Code to Read
- `xv6-riscv` source — small and complete.
- Linux kernel `kernel/sched/`, `mm/`, `net/ipv4/tcp*.c` — one subsystem at a time.
- `redis` source — small, fast, well-engineered C.
- `sqlite` source — B-tree and VM in readable C.

### Projects
- [ ] Rewrite `malloc` in C with a bump allocator → free-list → buddy.
- [ ] SIMD matmul in Rust hitting ≥80% of a BLAS baseline for one shape.
- [ ] Complete xv6 labs: syscall, pgtbl, traps, copy-on-write, threads, locks, fs, mmap, net.
- [ ] Ship an eBPF tool that solves a real problem (e.g., per-container TCP retransmit map).
- [ ] Submit one Linux kernel patch to a janitorial list (kernel-newbies / cleanups) and get it merged.

## The Fusion Capstone — CPU LLM Inference Engine

Your 2026 capstone ties the two tracks. Build a **CPU-only inference engine** in Rust:

- Load a small open-weights model (TinyLlama / Pythia-160m / similar).
- Implement the forward pass: embedding, attention (no optimizations yet), FFN, LN, sampling.
- Measure tok/s, identify the bottleneck (hint: matmul memory bandwidth).
- Add SIMD for the hottest kernel.
- Write a blog post with flame graphs.

This is the foundation on which 2027's GPU engine will be built. You cannot understand what GPUs fix unless you have felt the CPU bottleneck yourself.

## What NOT to Do in 2026

- Don't touch CUDA. Delayed gratification. You need the CPU pain first.
- Don't read MLIR/LLVM source. Year 2028.
- Don't train large models. You have no GPUs and no reason yet. Train small and understand.
- Don't skip xv6 labs because "I already know OS." The labs *are* the knowing.
- Don't read the latest arXiv paper before finishing the canon.
- Don't touch hardware (Chisel, FPGA). Year 2029.
